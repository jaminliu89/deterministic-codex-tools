# 安全与防破坏边界

- 不包含自动 reset/restore/checkout/clean/revert、rm、commit、push、merge、tag 或模型调用。Git 查询只读；唯一 Git 配置写入是用户显式 hooks --apply 的 local core.hooksPath，先拒绝任何已有设置/原生 hook。
- init/docs 默认预览，全组冲突预检、wx 写入，不覆盖旧资产。AGENTS 已有保留。拒绝穿越/绝对相对目标/.git/软链/硬链/特殊文件；根必须真实绝对目录。不自动创建仓库或移动历史版本。
- 单项目锁使用 exclusive create，仅拥有 inode 可释放；不按时间删他人锁。中断/中途失败保留已创建文件和目录，不自动删除；检查现场后人工恢复。
- 不是针对同权限恶意并发写者的隔离机制：预检到打开之间 TOCTOU、目录被替换、证据文件被手改等仍有风险。外部 OS 沙箱、只读源码快照及认证服务端审查才是更强边界。
- `--run` 执行明确 argv、不用 shell，cwd 固定项目，但代码可自行删文件/联网/派生子进程。只对可信且已审阅的命令使用。超时杀直接进程，不保证所有后代退出；processIsolation=NOT_VERIFIED，不读取/终止无关进程。
- 继承宿主环境供已有项目使用；不代表凭据隔离。对陌生项目应外部容器/低权限环境运行，并去掉 secrets。不存在自动下载依赖或授权模型费用。
- secret/Mock 静态扫描、日志脱敏是有限启发式。报告仅列发现类型与文件，不输出命中值；已知 token/键/URI 密码脱敏。未知格式、拆分/编码秘密、凭据输出到其他文件不能保证检出。需要项目自己的安全扫描/真实 auth/租户/CORS/恢复测试。
- 文档契约证明章节完整，不证明产品语义。artifact 非空不证明 seed/health 正确；必须在 checks 中配置实际行为。身份声明不是签名认证；手写 PASS 可造假，服务端 PR review 由独立系统验证。
- 识别出的收据 JSON 与依赖目录不应作为业务输入；其他证据目录文件仍纳入绑定；本机 receipts 非防篡改存储。依赖目录漂移、未知二进制、网络供应链、全平台行为保持 NOT_READY。
- MCP 绑定启动根，仅三个工具，无命令执行/路径切换/模型 API。仅 MCP 2025-11-25 stdio；不实现新版 stateless 协议，不公开网络端口。stdio 限帧1MB，串行处理。不要拿 MCP 工具替代宿主授权和权限设置。
